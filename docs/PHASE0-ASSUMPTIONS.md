# Zenithium — Phase 0 · Assumption Log

Every decision below was made under the "decide, do not ask" rule (§0.2). Each row states
the decision, why it is the most defensible option, and the single change that reverses it.

| ID | Area | Decision | Rationale | Reverse by |
|---|---|---|---|---|
| NAME-1 | Product | Product, module, bundle prefix and all type prefixes are `Zenithium`. The spec's `ApexError` becomes `ZenithiumError`; `ApexEngine/` becomes `Zenithium/`. | The user renamed the app to Zenithium; a half-renamed codebase (Apex types inside a Zenithium target) is the worse outcome. Behaviour is identical. | Rename `ZenithiumError` → `ApexError` and the target/folder `Zenithium` → `ApexEngine`. |
| ARCH-1 | Architecture | Two folders exist beyond the §6 tree: `Support/` (OSLog category vendor, `Clock` abstraction) and `Domain/EngineIO/` (engine input/output value types). | `Domain/` is specified as Foundation-only Sendable value types; OSLog is not that. Engine IO types must be visible to both `Engines` and `ViewModels`, so they live in `Domain`, grouped for navigability. | Move `Support/*` into `App/` and flatten `Domain/EngineIO/*` into `Domain/`. |
| ARCH-2 | Architecture | Engines are `enum` namespaces with `static func`, not `struct`. | §9 declares `struct X { static func … }`; an `enum` is the same call-site API with no accidental instantiation. `Zenithium.RecoveryEngine.compute(_:)` is unchanged for callers. | Change `enum` → `struct` in the six engine files. |
| API-1 | HealthKit | Wrist temperature is read from `HKQuantityTypeIdentifier.appleSleepingWristTemperature` (iOS 16+, Series 8+). Availability is probed at runtime with `HKHealthStore.isHealthDataAvailable()` plus an authorization-status check; unsupported hardware takes the §4.3 renormalization path. | The identifier exists in the iOS 18 SDK, but the *data* only exists on Series 8/Ultra. Treating "no samples" as "unsupported" is the only device-agnostic test available on-device. | Replace `TemperatureAvailability.probe` with a hardcoded `.unsupported`. |
| API-2 | HealthKit | `HKCharacteristicTypeIdentifier.biologicalSex` returns `HKBiologicalSex`; `.notSet` and `.other` both map to the spec's "female / unspecified" TRIMP constants (b = 0.86, c = 1.67). | §5.3 names only `male` and `female / unspecified`. Defaulting the unknown case to the higher-`b` constants avoids under-reporting strain for users who did not disclose sex. | Change the `default:` arm of `TRIMPConstants.for(_:)`. |
| API-3 | HealthKit | **Windowed reads** (a day of intraday HR, a night of sleep, workouts in a range) use `HKSampleQuery`. **Anchored queries with persisted anchors** drive change detection and deletion handling, one per observed type. | A windowed read must be idempotent and complete — it recomputes a whole day — while an anchor is a position in a stream, not a window. Using an anchor for windowed reads would make "recompute yesterday" return nothing. §8's anchored-query and deletion requirements are met by the change-detection path, which is what they exist for. | Point `fetchIntradayHeartRates` at `runAnchoredQuery` and drop its date predicate. |
| API-4 | HealthKit | Daily aggregates (RHR, HRV, respiratory rate, wrist temperature) use `HKStatisticsCollectionQuery` with `.discreteAverage`, anchored at local midnight of the query start. | §8 mandates `HKStatisticsCollectionQuery`; `.discreteAverage` is the documented option for discrete quantity types. | Change `StatisticsOptions` in `HealthKitTypeCatalog.aggregationOption(for:)`. |
| API-5 | HealthKit | Background delivery is requested at `.hourly` frequency for sleep, HRV, RHR and workouts. | Apple caps sleep/HRV to hourly-or-slower in practice; requesting `.immediate` on non-immediate types is silently downgraded and burns budget. | Change `HealthKitService.backgroundFrequency`. |
| DAY-1 | Strain | Day boundary = **wake time** (`DayBoundary.wakeAnchored`), falling back to local 04:00 when no sleep record exists. | Matches the spec's stated preference and the Whoop-style physiological day; the 04:00 fallback avoids a day that never starts when the watch was not worn. | Set `DayBoundary.default = .midnight` in `EngineConstants`. |
| STRAIN-1 | Strain | Monotonicity is enforced by storing a per-day `strainAnchor` (TRIMP accumulated up to `anchorTimestamp`) and only ever adding forward segments; a recompute takes `max(previous, recomputed)`. | §5.3 requires a recompute never to lower a displayed value, while still allowing HealthKit late-arriving samples to raise it. | Delete the `max(previous, recomputed)` clamp in `StrainEngine.compute`. |
| STRAIN-2 | Strain | Sample gaps: `Δt` is clamped to `[0, 60] s`; a gap **> 120 s** contributes zero (the sample after the gap opens a new segment). Gaps in `(60, 120] s` contribute the clamped 60 s. | §5.3 states both rules; this is the only reading under which both the 60 s clamp and the 120 s cut-off are meaningful. | Change `EngineConstants.Strain.maxGapSeconds`. |
| HRMAX-1 | Strain | If age is unavailable, age = 35 → Tanaka HRmax = 183.5 bpm. Logged at `.notice` on every use. | Spec §5.3 mandates exactly this. | Set `UserProfile.age` or `hrMaxOverride`. |
| HRMAX-2 | Strain | "Observed 12-month max HR" is the 99.5th percentile of the trailing 365 days of intraday HR, not the raw maximum. | A single artefact sample (belt dropout, 220 bpm spike) would otherwise permanently inflate HRmax and depress every future strain score. | Set `EngineConstants.Strain.observedMaxPercentile = 1.0`. |
| SLEEP-1 | Sleep | The scored night is the longest contiguous asleep block whose midpoint falls in `[18:00 prev day, 12:00 today]`; everything else that day is a nap. | §5.5 requires the midpoint from the longest contiguous asleep block; a window is needed to stop an afternoon nap from becoming "the night" for shift-pattern data. | Change `EngineConstants.Sleep.nightWindow`. |
| SLEEP-2 | Sleep | Contiguity tolerates gaps ≤ 15 min between asleep segments (Apple emits many short `.awake` interruptions); an `.awake` run > 15 min splits the block. | Without a tolerance, a normal night fragments into 6–10 "blocks" and the longest one is ~90 min, which would break every downstream metric. | Change `EngineConstants.Sleep.contiguityToleranceSeconds`. |
| SLEEP-3 | Sleep | `timeInBed` = union of `.inBed` intervals if present, else the span from first-asleep to last-asleep of the scored night. | Many sources never write `.inBed`; efficiency would otherwise be undefined for them rather than ~1.0. | Change `SleepInput.timeInBedSeconds` derivation in `SleepWindowResolver`. |
| SLEEP-4 | Sleep | Sleep debt decays 25 %/night and is computed over the trailing 7 nights, contributing `min(debt, 1.5) h` to need. Nap credit counts naps ≥ 20 min from the **previous calendar day**, capped at 1.0 h. | Spec §5.2 verbatim; the only free choice was "previous day" for naps, which is the day whose sleep pressure the night actually clears. | Change `EngineConstants.Sleep.napLookbackDays`. |
| SLEEP-5 | Sleep | Consistency uses the 14-day mean of night midpoints in **minutes-from-local-midnight, circular mean**, so 23:50 and 00:10 average to 00:00 rather than 12:00. | A linear mean of wall-clock midnights is catastrophically wrong for late-night sleepers. | Replace `CircularMean.midpointMinutes` with an arithmetic mean. |
| BASE-1 | Baseline | One `BaselineState` row per metric per user, keyed by `metric` (unique). Seeding uses the first ≥ 3 valid days; with fewer, `V₀ = σ_prior²`. | §4.2.6 verbatim. | Change `BaselineEngine.seed`. |
| BASE-2 | Baseline | Winsorization is skipped while `n < 3` (no trustworthy σ yet); the raw value is stored and the raw/clamped pair is logged either way. | Clamping against a one-sample σ would freeze the baseline near its first value. | Change `EngineConstants.Baseline.minSamplesForWinsorization`. |
| BASE-3 | Baseline | `ΔT` (wrist temperature delta) keeps its own EWMA of the **absolute temperature**, and the delta is `today − μ_yesterday`. HealthKit's own delta is not used. | `appleSleepingWristTemperature` is an absolute °C reading on some sources and a delta on others; deriving our own delta from our own baseline is source-independent. | Set `TemperatureMode.healthKitDelta` in `EngineConstants`. |
| CIRC-1 | Circadian | Anchors are injectable via `CircadianAnchors`; the default is the spec's midpoint-relative offsets. A second built-in preset, `.wakeAnchored`, is provided but not default. | The spec flags this as a SPEC RISK and requires the injection point. | Set `CircadianAnchors.default = .wakeAnchored`. |
| CIRC-2 | Circadian | The arc is sampled at 5-minute resolution (288 points/day) and wraps circularly by duplicating the anchor set at ±24 h before PCHIP fitting. | Gives a smooth chart at AX5 sizes without a per-frame solve, and makes the wrap seam C¹-continuous. | Change `EngineConstants.Circadian.sampleIntervalSeconds`. |
| MUSCLE-1 | Muscle | The involvement matrix covers 30 activity types (the 7 normative rows plus 23 derived by the same logic), declared as `Domain/WorkoutActivity.swift` so the matrix needs no HealthKit import. Any unlisted type maps to a `.generalWholeBody` low-involvement row rather than to zero. | §5.4 requires completing the matrix "by the same logic"; a zero row would silently drop real training load. | Return `[:]` from `MuscleInvolvementMatrix.fallbackRow`. |
| MUSCLE-2 | Muscle | `traditionalStrengthTraining` and `functionalStrengthTraining` contribute **zero** muscle impact from HealthKit; only a logged `StrengthSessionLog` produces their impacts. Their TRIMP still counts toward daily strain. | §5.4 forbids fabricating strength muscle data, but the cardiovascular cost of the session is real. | Add a row for those types in `MuscleInvolvementMatrix`. |
| MUSCLE-3 | Muscle | Fatigue is projected on demand from the trailing 14 days of sessions (`> 14 d` contributes < 1 % at the shortest half-life); `MuscleFatigueSnapshot` is a cache, never the source of truth. | Keeps the projection pure and recomputable after a formula change, per the `engineVersion` backfill rule (§7). | Change `EngineConstants.Fatigue.projectionWindowDays`. |
| RPE-1 | Muscle | `sessionLoad` for logged strength = `clamp(Σ(sets · reps · RPE) / 3.0, 0, 100)` where RPE ∈ [1, 10] is per-exercise, and `sets · reps` is the completed volume the user entered. | §5.4 verbatim; the only free choice was RPE granularity (per exercise, not per set) which keeps the logger to three fields. | Move `rpe` onto `StrengthSetEntry` in `StrengthSessionLog`. |
| ZONE-1 | Strain | The six HR zones are `%HRR` bands `[0–20, 20–40, 40–60, 60–80, 80–90, 90–100]`, stored as `zoneSecondsRaw: [Int]` in fixed order. | §7 mandates six zones without defining them; %HRR bands are consistent with the strain model's own `x(t)` and need no second HRmax convention. | Change `EngineConstants.Strain.zoneUpperBounds`. |
| STORE-1 | Persistence | The `@ModelActor` store never returns `PersistentModel` instances across its boundary — it returns `Sendable` snapshot structs declared in `Persistence/StoreSnapshots.swift`. | SwiftData models are not `Sendable`; returning them would be a Swift 6 data race. | Not reversible without breaking strict concurrency. |
| STORE-2 | Persistence | The container is created with `ModelConfiguration(schema:url:)` inside the App Group container so the widget extension reads the same store read-only. | §10 requires a shared App Group for widgets; a duplicated store would drift. | Point `ModelContainerFactory.storeURL` at the app sandbox. |
| STORE-3 | Persistence | `SchemaV1` is the only version; `ZenithiumMigrationPlan` declares `stages: []`. | §7 permits empty stages, requires the type to exist. | Add a `SchemaV2` and a `MigrationStage`. |
| BG-1 | Background | One `BGAppRefreshTask` id `com.zenithium.refresh.daily`, rescheduled on every completion, earliest begin = wake time + 30 min (fallback 06:00 local). | Post-wake recompute is the only scheduled work; `BGProcessingTask` is unnecessary for a sub-second engine pass. | Change `BackgroundRefreshScheduler.taskIdentifier` / `earliestBeginDate`. |
| BG-2 | Background | Background HealthKit delivery drives an `AsyncStream<HealthChangeEvent>` consumed by `HealthObservationRelay`, which debounces 30 s and single-flights into the coordinator. | Prevents an observer storm (HealthKit can fire many times per sync) from running the pipeline dozens of times. | Change `EngineConstants.Orchestration.observerDebounceSeconds`. |
| UI-1 | Views | The muscle map body is drawn with SwiftUI `Path`/`Canvas` from a vector table in `BodyGeometry.swift` — no image assets, no `UIViewRepresentable`. | Keeps the app asset-free, scales cleanly to AX5, and lets each of the 16 regions carry its own accessibility element. | Replace `BodyGeometry` with an asset catalogue and hit-test rectangles. |
| UI-2 | Views | Bands are always encoded with colour **and** a glyph + text label (`●▲■` + "Green/Yellow/Red"). | §10 accessibility gate: no colour-only encoding. | Not reversible — accessibility requirement. |
| UI-3 | Views | `.sensoryFeedback(.impact, trigger:)` fires only on a *band change* (Red↔Yellow↔Green), never on every value tick. | Haptics on every refresh would be noise; §10 asks for feedback "on band transitions". | Change the trigger in `RingGauge`. |
| WIDGET-1 | Widgets | Widgets read a small `WidgetSnapshot` JSON file in the App Group, written by the coordinator, instead of opening the SwiftData container. | Widget extensions have a tight memory budget and a read-only need; a JSON snapshot avoids container-open cost and schema coupling. | Point `WidgetTimelineProvider` at `ModelContainerFactory.makeReadOnly()`. |
| BUILD-1 | Build | `project.yml` is the authoritative project definition; `Scripts/generate-project.py` turns it into a checked-in `Zenithium.xcodeproj` with no tool installed. Both are committed. | The app needs an app target, a widget extension, an App Group and two entitlement files, which SwiftPM cannot express. Hand-writing a `.pbxproj` with 150+ file references and synthesised identifiers is not reviewable and cannot be checked here, so the project is *generated* from a spec a human can read, deterministically — identifiers hash from role and path, so an unrelated change produces a minimal diff. `xcodegen generate` produces an equivalent project from the same `project.yml`. | Delete the script and maintain the `.pbxproj` by hand. |
| TEST-1 | Tests | Tests live in a `ZenithiumTests` unit-test target that links the app target and imports `@testable import Zenithium`. Engine tests touch no HealthKit and no SwiftData. | §11 requires Swift Testing suites that run without HealthKit. | N/A. |
| TEST-2 | Tests | Golden-vector tolerance is `±0.05` absolute, implemented as a shared `#expect(abs(a - b) < 0.05)` helper `expectClose`. | §11 verbatim. | Change `GoldenTolerance.default`. |
| LOG-1 | Logging | `OSLog` subsystem = bundle id `com.zenithium.app`; categories: `health`, `engine`, `store`, `orchestration`, `ui`, `widget`. Raw biometric values are logged at `.debug` only and marked `privacy: .private`. | Health data must not leak into sysdiagnose; `print()` is banned (§2.4). | Change `ZenithiumLog.subsystem`. |
| SAFE-1 | Copy | All user-facing low-recovery copy is training-directive only, drawn from a single `SafetyCopy` table so no view can invent health-status language. | §12 compliance is easier to audit when the strings live in one file. | N/A — compliance requirement. |
| CONST-1 | Engines | Domain taxonomy types own the numbers that *define* the taxonomy — band cut-offs, σ floors, population priors, mass-class membership, zone bands, RPE range. `EngineConstants` owns every number used in a *formula* and forwards to the taxonomy types where the two overlap. | Each value keeps exactly one definition site, which is the point of the §9 rule. Putting σ floors in `EngineConstants` alone would force `Domain` to depend on `Engines`, reversing an arrow in §6. | Move the literals into `EngineConstants` and have the taxonomy types read them from there. |
| STORE-4 | Persistence | `MuscleFatigueSnapshot`'s natural key is a derived `snapshotKey: String` (`"<epoch>-<engineVersion>"`) carrying `@Attribute(.unique)`, rather than a compound unique constraint. | Keeps the schema to the one attribute macro §7 names, with no dependence on a compound-uniqueness macro. The key is derived in one `static func` so it cannot drift from its components. | Replace `snapshotKey` with a compound unique constraint over `computedAt` and `engineVersion`. |
| BASE-4 | Baseline | Wrist temperature blends only its **σ** toward the population prior during cold start; its mean stays fully personal. | Its prior is stated on the `ΔT` scale (mean 0) while its EWMA tracks the absolute reading (BASE-3). Blending an absolute mean toward 0 would be meaningless. Every other metric blends both, per §4.2.4. | Store a delta-scale EWMA for temperature and blend both terms. |
| API-6 | HealthKit | `authorizationReport` reports only what HealthKit will actually tell us — whether the sheet still needs showing (`getRequestStatusForAuthorization`). A genuine denial is detected when a query fails with `HKError.errorAuthorizationDenied`, which maps to `ZenithiumError.healthAuthorizationDenied` and drives the §5.6 Settings gate. | HealthKit deliberately never reports read authorization: a denied read returns empty results, not an error, so that apps cannot infer that a user is hiding a condition. Guessing "denied" from empty results would show the Settings gate to every new user with a fresh watch. | Infer `.denied` in `authorizationReport` when the request status is `.unnecessary` and a probe query returns nothing. |
| API-7 | HealthKit | Every `HealthDataProviding` requirement is `async`, and the read methods take the `Calendar` to bucket in. | An `actor` cannot witness a synchronous protocol requirement without going `nonisolated`, which would defeat the isolation §8 asks for; and §2.7's rule against un-injected date computation applies at the boundary that produces day buckets. Shapes are otherwise exactly as §8 specifies. | Mark the methods `nonisolated` and read `Calendar.current` inside them. |
| API-8 | HealthKit | Overnight metrics are averaged over the sleep window widened by 2 h on each side. | HealthKit writes resting heart rate and wrist temperature as day-spanning samples that need not lie strictly inside the sleep interval; a strict window would drop them and trigger a spurious §4.3 renormalization. | Change `HealthKitService.overnightWindowPadding` to 0. |
| API-9 | HealthKit | The observer query's completion handler is invoked **before** the anchored change-detection pass runs, not after. | `HKObserverQueryCompletionHandler` is not `Sendable` and cannot be captured by the `Task` that does the async work. Acknowledging first is safe because the anchor is persisted: a wake lost to termination is caught up on the next pass rather than dropped. | Wrap the handler in a `Sendable` box and call it after `processChanges` returns. |
| MOCK-1 | Testing | `MockHealthProvider` derives every value from a pure hash of (seed, day index, channel) rather than from a stateful generator. | Order-independence is what makes the §11 pipeline test assertable: the same calendar day yields the same number no matter which query asks, in what order, or how many times. A stateful LCG would make results depend on call sequence. | Replace `mix` with a stored `SystemRandomNumberGenerator` seeded per instance. |
| RECOV-1 | Recovery | When a term is dropped, the surviving weights are divided by **their own sum**, so they total 1.0. Missing temperature therefore gives 0.4444 / 0.2778 / 0.2222 / 0.0556, not the 0.4211 / 0.2632 / 0.2105 / 0.0526 printed in §5.6. | §5.6's four figures divide by 0.95 and sum to 0.9474, which contradicts §4.3 and the §11 test that requires the weights to sum to 1.0. §5.2's unstaged renormalization in the same specification divides by the surviving sum and does reach 1.0, so §5.6 is an arithmetic slip, not a second rule. Following it would shrink every no-temperature score toward the middle by about 5 %. | Replace `MathSupport.renormalize` in `RecoveryEngine` with a divide by `1 − droppedWeight/2`. |
| CONST-2 | Architecture | `EngineConstants` and `MathSupport` are **leaves**: each reads `Domain` and nothing else, and every layer may read them. | Lets `Health` take its downsampling interval, `Models` take its sleep-need default, and a view clamp a ring's progress — each from the one place that thing is written, without any of them depending on the engines and without a second copy of the same three lines. Both files are pure, stateless and Foundation-only, which is what makes the exception safe. | Move the shared values into `Domain` and have both files forward to them. |
| CIRC-3 | Circadian | The recovery amplitude scale **multiplies** alertness rather than compressing it toward a midline. | Keeps the §11 invariant structural — the curve cannot exceed 100 for any recovery value — and reads correctly: a depleted day dulls peaks and troughs alike. Compressing toward a midline would *raise* the night trough on a bad day. | Scale deviations from the anchor mean instead of the values themselves. |
| BG-3 | Background | A one-shot `BackgroundTaskBox: @unchecked Sendable` carries the `BGAppRefreshTask` into the structured task that completes it. | `BGTask` is not `Sendable`, and both usual escape hatches are closed: §2.4 bans `DispatchQueue`, so the launch handler cannot be registered on the main queue, and the handler must call `setTaskCompleted` *after* async work or the system terminates the app. The box is created inside the handler, handed to exactly one task, never stored and never read twice; `setTaskCompleted(success:)` is documented as callable from any thread. This is the only `@unchecked Sendable` in the codebase. | Register the launch handler with `using: DispatchQueue.main` and drop the box. |
| MUSCLE-4 | Muscle | A workout's TRIMP is re-integrated from the intraday series over the workout's own interval — one bounded query per workout in the 14-day window — rather than apportioned from the daily total. | A session's contribution to muscle fatigue then does not change when the rest of the day does. Apportioning would make this morning's run look heavier every time the user walked in the evening. | Estimate from `WorkoutSummary.averageHeartRate` × duration instead. |
| STORE-5 | Persistence | `DayRecordWrite` treats `nil` as "not computed this pass, leave the stored value alone". A separate `clearsOvernightValues` flag is what erases the overnight block. | A strain-only refresh at 6 pm must not clobber the morning's recovery score, so absent ≠ zero. But §5.6 requires deleted HealthKit samples to remove the score they produced, and that needs an explicit instruction rather than the absence of one. | Make every field non-optional and always write the whole record. |
| SLEEP-6 | Sleep | Historical shortfalls in the 7-night debt window are measured against the profile's current `baselineNeed`, not against each night's own computed need. | Each night's need depends on that night's debt, so using it would make the debt term self-referential. The profile baseline is the stable reference the recursion needs to bottom out on. | Persist `needHours` on `BiometricDayRecord` and measure each shortfall against its own night's need. |
| ORCH-1 | Orchestration | When a night cannot be scored, the fatigue engine is given a sleep score of 58.33, not 0 or 100. | It is the value that yields a 1.0× half-life modifier (`1.35 − 0.006·x = 1.0`), so an unknown night neither accelerates nor stalls muscle recovery. 100 would clear fatigue at the fastest rate the model allows and 0 at the slowest — both are claims Zenithium has no basis for. | Change `DailyRecalculationCoordinator.neutralSleepScore`. |
| VM-1 | ViewModels | `ViewState` carries a `.loading` case in addition to the five §10 names. | A view model must be in *some* state before its first read completes. Starting in `.noData` would flash "no data" on every launch, which is a lie about the data rather than a description of it. | Delete the case and start in `.noData(reason:)`. |
| VM-2 | ViewModels | Observation teardown is an explicit `onDisappear()` the view calls, not a `deinit`. | `deinit` is nonisolated, so reading a `@MainActor` stored property from it is a strict-concurrency error under Swift 6. An explicit method also cancels at the moment the screen goes away rather than whenever the object happens to be released. | Adopt `isolated deinit` and move the cancellation back. |
| VM-3 | ViewModels | Picker changes call `select(metric:)` / `select(range:)` rather than using `didSet` on `@Observable` properties. | The `@Observable` macro rewrites stored properties into accessors; layering a property observer on that is needless subtlety when the picker can call a method that also owns the reload. | Restore the stored properties with `didSet` observers. |
| VM-4 | ViewModels | An authorization failure becomes `.needsAuthorization`, not `.failed`; a cancellation returns `nil` and leaves the previous state alone. | Permission is something the user can grant, not a fault to apologise for (§5.6), and a cancelled refresh should not blank a screen that already had content. | Return `.failed(error)` for every case in `ViewState.from(_:)`. |
| UI-4 | Views | Rings are drawn with `GraphicsContext.Shading.conicGradient` inside `Canvas`. | §10 asks for an `AngularGradient`, but inside a `Canvas` there is no view to apply one to; a conic shading is the same sweep expressed as a shading. | Draw the ring as a `Circle().trim(...)` with an `AngularGradient` and drop the `Canvas`. |
| UI-5 | Views | The settings deep link uses the literal `"app-settings:"` rather than `UIApplication.openSettingsURLString`. | UIKit is not on the §2.2 framework list, and importing it for one string constant would widen the app's surface for nothing. The value is a documented, stable system URL. | Import UIKit and use the constant. |
| UI-6 | Views | Curves the engine has already sampled — the circadian arc — are drawn in `Canvas`; Swift Charts is reserved for plotted data series. | 288 samples render in one `Canvas` pass, and the arc's meaning lives in its six named markers, which become their own accessibility elements. §10's `.accessibilityChartDescriptor` requirement applies where Swift Charts is used, which is Trends. | Rebuild `CircadianArcView` on `Chart` with a `LineMark` per sample. |
| UI-7 | Views | `Views/Trends/TrendChart.swift` imports `Accessibility` for the `AX…Descriptor` types. | §10 mandates `.accessibilityChartDescriptor` on Swift Charts, and those types live nowhere else. The framework is first-party and adds no capability beyond describing a chart to VoiceOver. | Drop the descriptor and rely on per-mark accessibility labels. |
| UI-8 | Views | The body map draws nine regions per side, and a full 16-row list sits beneath it. | Each drawing can only show the groups that face the viewer, so the list is what makes all sixteen reachable — and it gives VoiceOver a linear order rather than only a canvas of hit areas. | Remove the list and add front/back toggles to every group. |
| UI-9 | Views | The bloodwork range bar is monochrome, and the marker dot is white regardless of where it sits. | §12 forbids interpreting a value. Colouring the bar by position would be exactly that — a red dot is a verdict, whatever the caption says. | Tint the dot by whether it falls inside the reference range. |
| VM-5 | ViewModels | `HealthAuthorizing` is declared in `Health/` and inherited by `HealthDataProviding`. | Lets a view model take the narrow permission surface without a cast in the composition root, and keeps the arrow pointing down: view models depend on `Health`, never the reverse. | Declare it in `ViewModels` again and cast at the root. |
| BUILD-2 | Build | `NSHealthUpdateUsageDescription` is deliberately absent from `Info.plist`. | §8 lists it "(if writing)", and Zenithium never writes to Health — its share set is empty and its read set is declared in `HealthKitTypeCatalog.readTypes`. Declaring a write purpose the app does not have would be a false statement on the permission sheet and an entitlement it does not need. | Add the key and a truthful description if a write path is ever introduced. |
| BUILD-3 | Build | Targets have an empty `PBXFrameworksBuildPhase`; frameworks are auto-linked from Swift `import`. | Swift auto-links every framework a target imports, so an explicit phase would be a second list to keep in sync with the imports — and a stale one is how a target ends up linking something it no longer uses. | List the frameworks explicitly in `Scripts/generate-project.py`. |
| BUILD-4 | Build | `SWIFT_TREAT_WARNINGS_AS_ERRORS` is on in **Release only**. Debug builds warn without failing. | §2.1 requires zero warnings in what ships, and Release plus CI enforce exactly that. Making Debug fatal too only means a single unused-variable warning blocks a device build during bring-up — cost with no safety gain, since nothing is shipped from Debug. | Set it to `YES` in `debug_extra` and regenerate. |
| LAB-1 | Labs | `LabDocumentReader` imports PDFKit and Vision, neither on the §2.2 framework list. | Both are first-party, both run entirely on device, and neither adds a capability beyond reading a file the user handed us — no network, no service, no model download. Manual entry keeps working if they are removed. | Delete `LabDocumentReader` and keep `BloodMarkerEditorView`. |
| LAB-2 | Labs | Pages are rasterised at 2× in greyscale before optical recognition. | Laboratory reports are black text on white, so colour carries nothing and greyscale halves the buffer; below 2× the small print starts losing digits, which is the one thing a medical number cannot afford. | Change `renderScale` and the colour space in `LabDocumentReader.image(of:)`. |
| LAB-3 | Labs | Nothing the parser produces is written until a person has approved it row by row, and low-confidence rows arrive **switched off**. | Optical recognition misreads digits. Opting *in* to a guess is a different risk from having to notice and opt *out* of one, and only the first is acceptable for a medical value. | Preselect every row in `LabImportViewModel.Row.init`. |
| LAB-4 | Labs | A printed value that is ambiguous between decimal and thousands ("1.234") is resolved against the marker's own reference band, not by locale. | Turkish laboratories print both conventions and the line itself never says which. A CK of 1.234 U/L is three hundred times below the band and 1234 U/L is an ordinary reading, so the band decides — and the row is still demoted to low confidence either way. | Remove `LabReportParser.resolveGrouping` and always take the printed decimal. |
